## 2. Project Context & Objectives

* **Target Hardware:** Redmi Note 14 5G (`beryl`, MediaTek Dimensity 7025 / MT6855).
* **GPU:** Imagination PowerVR B-Series BXM-8-256.
* **Architecture Correction:** This project is now treated as a **Volcanic-first bring-up target**. The local codebase still contains Rogue-era compatibility scaffolding, but those components are treated as historical infrastructure and not as final architecture truth.
* **Hardware BVNC:** `35.3.408.101` (Packed uint64: `0x0023000301980065`).
* **Kernel Driver:** Stock Imagination DDK `25.1@6715691` (`pvrsrvkm.ko`).
* **Primary End-Goal Applications & Target Performance:**
  * **Realistic Target:** Stable **720p 30 FPS handheld gaming** for 2D indies (*Celeste*, *Hollow Knight*, *Dead Cells*, *Undertale*), retro ports (*Pokémon* GBA/NDS classic ports, *Castlevania*), and lightweight JRPGs in **Eden / Yuzu / Azahar / Winlator**.
  * **Hardware Reality:** The Dimensity 7025 (2× Cortex-A78 @ 2.5 GHz, ~260 GFLOPS GPU) has ~3.5× higher CPU IPC and higher GPU compute than the original Nintendo Switch Tegra X1 in handheld mode (~196 GFLOPS). The hardware is not the bottleneck.
  * **Why Games Crashed on Stock Driver:** Stock MediaTek `libusc.so` compiler threw `SIGSEGV` segmentation faults when compiling NVN-to-SPIR-V translated shaders; stock DDK clamped push constants and had ASTC format view mismatches. Mesa's standard-compliant NIR compiler fixes these compiler crashes.
* **Target Delivery Mechanism (COMPLETED):**
  * Rootless **`adrenotools` `.zip` driver package** ([`dist/vulkan_pvr_bxm8256_adrenotools.zip`](dist/vulkan_pvr_bxm8256_adrenotools.zip)) for Eden and Azahar custom driver menus.
  * **Dual HAL (`HMI`) + ICD (`vk_icdGetInstanceProcAddr`, `vk_icdNegotiateLoaderICDInterfaceVersion`) exports** ([`dist/vulkan_pvr_bxm8256_icd.zip`](dist/vulkan_pvr_bxm8256_icd.zip)) for Winlator/DXVK.
  * Packager tool: [`tools/package_driver.py`](tools/package_driver.py) validates exports, DT_NEEDED, and generates zip bundles automatically.

### Run the Offline Feature Gates

> The gates read paths relative to their own file, so they run from any working
directory. Two of them (M17 ASTC, M18 depth clamp) also read the **generated**
CSB packet headers for bit positions and enum values. On a fresh checkout there
is no build tree, so run `python3 tools/gen_csb_headers.py` first — it runs
`csbgen/gen_pack_header.py` the same way meson does and writes the headers into
`research/mesa-src/build-android/src/imagination/csbgen/`. CI does exactly this.

```bash
python3 /home/ameya/bxm-research/tools/gen_csb_headers.py   # fresh checkout / CI only
python3 /home/ameya/bxm-research/test_multiviewport_wiring.py    # M21 multi-viewport feature/limit/clip wiring
python3 /home/ameya/bxm-research/test_int64_lowering.py          # M20 shaderInt64 lowering wiring
/home/ameya/bxm-research/tests/build_test_bc_decode.sh && /home/ameya/bxm-research/tests/test_bc_decode   # M23 BC decode kernel (30 checks)
python3 /home/ameya/bxm-research/test_astc_format_coverage.py   # M17 ASTC table consistency
python3 /home/ameya/bxm-research/test_depth_clamp_wiring.py      # M18 clamp/clip bit contract
python3 /home/ameya/bxm-research/test_volcanic_mock.py           # L1: XML / header / BVNC / meson wiring
python3 /home/ameya/bxm-research/test_volcanic_header_validation.py  # L2: generated header content
gcc -Wall -Wextra -O2 /home/ameya/bxm-research/tests/test_drm_shim_mock.c -o /home/ameya/bxm-research/tests/test_drm_shim_mock && /home/ameya/bxm-research/tests/test_drm_shim_mock
```

> **Milestone state note (2026-11-12):** M17 (ASTC), M18 (depth clamp) and M21 (multi-viewport) are implemented and host-validated; all three still need on-silicon verification. M19 (descriptor indexing) is **not** implementable by flipping feature flags: descriptors are uploaded into USC shared registers by a per-layout PDS descriptor-upload program, so a runtime array index cannot select a descriptor. M22 (GS/tessellation) needs a Parameter Buffer streaming design. See `PROJECT_STATUS.md` before starting either.
>
> **Build state note (2026-11-12):** Mesa commit `7f6bd1acab92` ("Refactor code structure...") renamed shared compiler/Vulkan sources from `ROGUE_*` to `VOLCANIC_*` before a Volcanic per-arch implementation existed, which left the tree with 368 compile errors. Those 57 files were restored to their pre-migration content (`a2eee7644388`) so the driver links again. The added Volcanic scaffolding (`src/imagination/csbgen/volcanic/`, `include/hwdef/volcanic_hw_*.h`, `vulkan/volcanic/*.c`) is still present but **not built**, and the BXM profile declares `.arch = PVR_DEVICE_ARCH_ROGUE` so dispatch targets the compiled implementation. Do not re-apply that rename without porting the per-arch code and defining the Volcanic constants it needs.

Gate: `python3 test_astc_format_coverage.py`. Native TPU sampling on silicon is still unverified.
* **Milestone 18 [COMPLETE / HOST-VALIDATED]:**
  * **ISP depth clamping:** `pvr_depth_clamp_enabled()` drives both `TA_STATE_PPP_CTRL.clip_mode` and `TA_OUTPUT_SEL.isp_position_depth_clamp_z`; `.depthClamp = true`. Gate: `python3 test_depth_clamp_wiring.py`. Silicon behaviour unverified, and the `VK_EXT_depth_clamp_zero_one` clamp range still needs on-silicon confirmation (see the M18 entry in `MILESTONE_EXECUTION_LOG.md`).
* **Milestone 21 [COMPLETE / HOST-VALIDATED]:**
  * **Multi-viewport:** `has_multiviewport` device bit declared in `pvr_device_info.h` and consumed by `.multiViewport = PVR_HAS_FEATURE(dev_info, multiviewport)`; `.maxViewports = PVR_MAX_VIEWPORTS` (16). The ISP scissor / TA region clip now uses the union of every (`viewport[i]`, `scissor[min(i, count-1)]`) overlap instead of asserting a single viewport. Gate: `python3 test_multiviewport_wiring.py` (9 checks, mutation-probed). On-silicon rendering unverified.
* **Milestone 20 [COMPLETE / HOST-VALIDATED]:**
  * **`shaderInt64`:** 64-bit ALU lowered to 32-bit pairs (`lower_int64_options = ~0U`) and 64-bit loads/stores split to 32-bit components by a new `pco_mem_access_size_align()` callback used with `nir_lower_mem_access_bit_sizes`. Gate: `python3 test_int64_lowering.py` (21 checks, mutation-probed). No 64-bit atomics; **Int8 / 8-bit storage is still off** (no `nir_lower_bit_size` hook in PCO).
* **Driver Feature Expansion Roadmap [PLANNED / THINGS TO DO]:** read [`MILESTONE_M19_M22_PLAN.md`](MILESTONE_M19_M22_PLAN.md) before touching either:
  * **M19 (Descriptor Indexing / Bindless):** blocked in Mesa, **not** in silicon — the vendor reports the whole descriptor-indexing set as `1.0`. The driver uploads descriptors into USC shared registers (uniform index only), so a per-lane index has nowhere to go. **Do not just flip the feature flags** — a 2026-11-12 attempt did that and was reverted (invalid Vulkan feature combination, no-op lowering).
  * **M20 remainder (Int8 / 8-bit storage):** add a `nir_lower_bit_size` hook in PCO, then enable `storageBuffer8BitAccess` / `shaderInt8` (vendor reports both as `1.0`).
  * **M22 (Geometry & Tessellation):** Implement intermediate Parameter Buffer (PB) streaming passes in PCO (emulating GS/Tess on TBDR).
  * **M23 (BC Texture Decompression):** Hardware lacks BC units (`0.0`); implement compute shader decompression for desktop textures in Winlator.
